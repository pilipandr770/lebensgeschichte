# Lebensgeschichte

Голосовое приложение-слушатель для создания автобиографии/мемуаров (в первую очередь для пожилых людей).
Человек разговаривает, ИИ слушает и поддерживает, из рассказов собираются книга, раскадровка комикса и «дорога жизни» (лента событий).
Целевой рынок: немецкоязычный (DSGVO, хранение в ЕС). Автор: Борух, самозанятый разработчик.

## Структура
- `src/backend/`: Flask API (`app/`), банк вопросов `app/data/questions.json`, сценарий знакомства `app/data/onboarding.json`, тесты `tests/`
- `src/frontend/`: React + Vite (большие кнопки, крупный шрифт, запись голоса с автоостановкой по паузе)
- `docs/`: полная документация (начинать с `docs/00-vision.md`, затем `docs/SETUP.md`)
- `tools/`: `validate_questions.py`, `seed_demo.py`
- `.claude/commands/`: слэш-команды для типовых задач

## Команды
- `make setup`, затем заполнить `.env` (см. `.env.example`, поля помечены ЗАПОЛНИТЬ)
- `make test` (backend unittest, должен проходить без ключей: mock-режим)
- `make validate` (проверка банка вопросов)
- `make dev-backend` и `make dev-frontend` (порты 8000 и 5173)
- `make up` (Docker, http://localhost:8080)

## Принципы (не нарушать)
1. ИИ всегда честно говорит, что он ИИ. Не врач и не психолог.
2. ИИ не выдумывает факты. Всё сгенерированное (события, главы) показывается человеку на подтверждение.
3. Человек главный: любой вопрос можно пропустить, любую тему закрыть, все данные удалить и выгрузить.
4. Чувствительные темы (потери, болезни, вера, трудное детство) только после явного согласия (gate), теги по ним только при открытом gate.
5. Кризисные фразы: фиксированный спокойный ответ, интервью не продолжается (`app/safety.py`). Не убирать, расширять и тестировать.
6. Приватность: данные в ЕС, ключи только в `.env`, аудио и транскрипты не логировать.
7. Короткие реплики слушателя, без советов и оценок (см. `app/prompts.py`).

## Соглашения
- Язык интерфейса и банка вопросов сейчас русский (черновик). Целевой язык продукта немецкий: перевод вопросов и промптов это задача из `docs/06-roadmap.md`.
- Условия `if` в банке вопросов вычисляет собственный безопасный парсер (`app/questions.py`), `eval` не использовать.
- Любое изменение логики вопросов сопровождать тестом в `tests/test_questions.py`.
