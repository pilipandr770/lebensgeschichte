# 01. Архитектура

## Схема
```
Браузер (React PWA-готовый SPA)
  ├─ запись голоса (MediaRecorder) + детектор пауз (WebAudio RMS)
  ├─ озвучка ответов (speechSynthesis браузера)
  └─ экраны: знакомство, настройка, разговор, дорога жизни, книга, комикс, настройки
        │  HTTPS /api
        ▼
nginx (раздаёт статику, проксирует /api)
        ▼
Flask API (gunicorn)
  ├─ auth: email+пароль, подписанный токен
  ├─ questions: движок банка вопросов (условия, ворота, приоритеты)
  ├─ stt: mock | faster-whisper (локально) | OpenAI-совместимый API
  ├─ llm: Anthropic API | mock (слушатель, извлечение, главы, комикс, итог)
  ├─ safety: кризисные фразы
  ├─ exports: книга md/html/pdf, архив данных zip
  └─ SQLite (/data/app.db) + аудиофайлы (/data/audio/<user>/)
```

## Режим разговора: пошаговый, не реалтайм
Почему: пожилые люди говорят с паузами, реалтайм-агент перебивал бы; слушатель в основном молчит; точность на целой записи выше; проще и дешевле; сочетается с локальным Whisper.

Цикл:
1. Приложение показывает и озвучивает вопрос.
2. Человек нажимает «Рассказать» и говорит. Запись останавливается сама, когда пауза дольше порога из настройки (3, 6 или 10 секунд), либо кнопкой «Закончить».
3. Аудио уходит на `/api/turn`: распознавание, сохранение, извлечение тегов, короткая реакция слушателя (по настройкам), расчёт следующего вопроса.
4. Приложение озвучивает реакцию. Кнопки «Рассказать ещё» и «Дальше». В режиме «интервьюер» дальше идёт автоматически. Настройка «сразу включать запись» перезапускает запись после озвучки вопроса.

## Поток знакомства и настройки
- **Этап A (скрипт):** 7 коротких шагов: «я ИИ», цель, правила, приватность. `onboarding.json`, `stage_a_intro_script`.
- **Этап B (мастер):** 23 вопроса о поведении, один на экран (роль, паузы, тон, юмор, реакция на грусть, табу-темы, формат, порядок, результат, семья, завершение). Ответы сохраняются в `settings`.
- **Этап C:** пробный разговор по вопросам знакомства (модуль `intro`).
- **Этап D:** настройки влияют на системный промпт слушателя (`prompts.py`), порог паузы, выбор вопросов и порядок.

## Движок вопросов (`app/questions.py`)
- Теги профиля (`children`, `partner_now`, `moved` и т.д.) извлекаются ИИ из свободных ответов, а не из анкеты. Значения: `true`, `false` или неизвестно.
- Условие `if` у вопроса или модуля: `children`, `children == false`, `unknown(children)`, `a && b`, `a || b`, `!a`, `'book' in output_forms`.
  Разница между «нет» и «не знаем»: `!x` не используется там, где важна разница, вместо этого `x == false`.
- Порядок: знакомство → (опционально самое яркое) → модули по порядку. Режимы `chronological`, `by_theme`, `free` (выбор темы), `brightest_first`.
- Приоритет `p=1` задаётся первым, `p=2` только если сессия не короче 10 минут.
- Чувствительные модули (`hard`, `values`) сначала показывают «ворота» с согласием. Для слушателя и режима «менять тему» они откладываются до 4-й сессии.
- Два пропуска подряд: предложение паузы или смены темы. После тяжёлого вопроса идёт светлый «мостик».

## Модель данных (SQLite)
`users`, `profiles` (настройки, теги, состояние движка), `sessions`, `recordings` (аудио, транскрипт, вопрос, модуль, флаг кризиса), `events` (дорога жизни), `chapters` (книга, комикс). Удаление пользователя каскадно удаляет всё и стирает аудио (`DELETE /api/me`).

## Что и куда уходит
| Данные | Куда | Примечание |
|---|---|---|
| Аудио | Только на ваш сервер (`/data/audio`) | при облачном STT уходит провайдеру |
| Транскрипты | Anthropic API (реплика, извлечение, главы, комикс, итог) | нужен DPA, ЕС-режим по возможности |
| Теги и настройки | Только ваша база | чувствительные теги не извлекаются без согласия |
